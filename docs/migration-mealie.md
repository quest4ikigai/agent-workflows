# Migrating mealie-mcp-server to agent-workflows

This is a plan for a **future** change to `quest4ikigai/mealie-mcp-server`
(branch `agent-main`). Nothing in this repository modifies Mealie.

## Behaviour changes to be aware of

| Area | Before | After |
| --- | --- | --- |
| Retry a failed `[agent-build]` run | assign the issue to the owner | add (or remove and re-add) the `agent-build` label |
| Remediation eligibility | head branch starts with `claude/` | PR carries the `agent-review` label (Path A adds it automatically). **Existing open agent PRs need the label added once.** |
| `/agent-fix` scope | only `claude/` branches | any same-repository, unprotected PR branch; it opts the PR in |
| Who is trusted | `github.repository_owner` string match | `trusted_users` **and** live write/admin permission |
| Status comment author | the PAT owner | `github-actions[bot]`. Old status comments are ignored, so open PRs start a fresh 0/3 budget. |
| Validation | Claude self-reports | Claude runs `validate.sh`, then the workflow runs it again; a failure stops automation before Codex is asked |
| PAT permissions | Contents/Issues/PRs read-write | Contents **read-only**, Issues and PRs read-write |
| Initial Codex review wait | inside the implement job | separate job holding the per-PR lock |
| Path B | not available | label `agent-review` or `/agent-review` on any same-repo PR |
| Failures | silent unless Claude reported | issue/PR comment with the workflow run link |

`[agent-build]` titles, `/agent-fix`, the Codex request format
(`@codex review` + origin marker), clean-review detection, thread resolution, the
3-pass budget and the one-shot Opus audit + consolidated fix are unchanged.

## Steps (when ready)

On a branch from `agent-main`:

```bash
npx --yes github:quest4ikigai/agent-workflows#v1 install . --force --ref v1 --trusted-user quest4ikigai
git rm .github/workflows/agent-remediate.yml .github/scripts/agent-review-state.sh
cp <agent-workflows>/docs/examples/mealie-mcp-server/pr-footer.md .github/agent/pr-footer.md
```

Then:

1. Add the footer to `.github/agent/config.yml`:

   ```yaml
   pull_request:
     footer: .github/agent/pr-footer.md
   ```

2. Optional: Mealie's docs use `yarn install --immutable`; the installer infers
   `yarn install --frozen-lockfile` from `packageManager: yarn@1.22.22`. Either
   works with Yarn 1 — edit `setup.sh` if you want them identical.
3. Optional: add `WORKFLOWS.md` to `context:`.
4. Review `validate.sh` (it reproduces the existing suite: typecheck, lint,
   gen:docs:check, test, build).
5. Narrow `AGENT_GITHUB_TOKEN` to Contents read-only (Issues and Pull requests
   stay read-write).
6. Create the `agent-review` label, and consider protecting `agent-main`
   (`check` reports it as unprotected today).
7. Merge to `agent-main` (the default branch), run `agent-workflows check .`.
8. Add `agent-review` to any open agent PRs that should stay under automation.
9. Smoke-test Path B on a trivial PR, then Path A on a small issue.

## Rollback

Revert the merge commit: the old workflow files return and no state needs
cleaning up (old and new status comments are independent).
